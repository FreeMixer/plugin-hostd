# What omx-clap-host must send for plugin-hostd#131

plugin-hostd's side of #131 is built (the union-narrowed LV2 world, the relay of the preset, bundle and learn verbs,
parameter feedback declared). These are the parts that belong to the worker, omx-clap-core's lane. plugin-hostd does not
edit that repo; each line below is what the daemon already relays or expects.

1. **A chain of one.** `chain <chain> <instance>` with a single member is a valid line (`chain_members_min` is 1). The
   worker answers `resp 0` when it holds the member, as it does for a chain of two or more (omx-clap-core#104).
2. **A world of several bundles.** A chain's LV2 members run in one worker whose `LV2_PATH` is one directory holding a
   link to each member's bundle, each once. The adapter finds every member's uri in that world; a chain member must
   never answer `resp -101` because another member's bundle sits beside its own.
3. **Presets and bundles.** `preset_load <n> <uri>`, `preset_save <n> <name> <dir> <file>`, `preset_show <uri>`,
   `bundle_add <path>` and `bundle_remove <path> <resource>` are answered by mod-host's grammar instead of `resp -902`:
   preset_save writes the plugin's state as a preset file, preset_load loads it through the CLAP preset-load extension.
   An instance verb goes only to the worker that holds the instance; `preset_show` and the bundle verbs go to every
   worker. The daemon hands back whatever the worker answers.
4. **MIDI learn and CV addressing.** `midi_learn`, `midi_map`, `midi_unmap`, `cv_map` and `cv_unmap` are answered by
   mod-host's grammar instead of `resp -902`. The daemon's ledger keeps them and replays them after a respawn.
5. **Parameter feedback.** For every value the plugin moves by itself (its automation, an LFO, a preset load, a MIDI
   map, the user's knob of the plugin's own: the CLAP parameter out-events the plugin flushes), the worker writes
   `param_set <instance> <symbol> <value>` on its feedback port, as mod-host writes it. It never writes one for a
   value a controller's `param_set` gave it. The daemon relays each line as written, in order (protocol.h
   `PHD_EVENT_PARAM_SET`; held by
   `a_value_the_plugin_moved_by_itself_reaches_the_controller_and_a_controllers_value_writes_no_feedback`).
